# Smartphone Sales Analytics

Проект анализа продаж категории «Смартфоны» на основе SQLite, SQL и Python.
Подготовлен на базе исходного Google Colab-ноутбука: ноутбук сохранён в `notebooks/original_analysis.ipynb`,
а повторяемый запуск анализа вынесен в отдельный Python-скрипт.

## Что анализирует проект

1. Ежемесячную выручку, число заказов, средний чек и долю брендов.
2. Средние цены по брендам и трёхмесячное скользящее среднее.
3. Интервалы между последовательными покупками клиентов.
4. Маркетинговые расходы по месяцам, каналам и брендам.
5. Качество данных, динамику продаж, цены и retention когорт.

## Требования

- Python 3.10+
- SQLite (входит в стандартную библиотеку Python)
- Зависимости из `requirements.txt`

## Быстрый запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/ВАШ_ЛОГИН/smartphone-sales-analytics.git
cd smartphone-sales-analytics
```

### 2. Создать виртуальное окружение

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Добавить базу данных

Положите SQLite-файл `technomart.db` в папку `data/`.

Ожидаются таблицы:

- `products(product_id, brand, category, base_price)`
- `orders(order_id, customer_id, date, revenue)`
- `order_items(order_id, product_id, price, quantity)`
- `marketing_spends(date, channel, brand, amount)`

### 5. Запустить анализ

```bash
python src/analysis.py --db data/technomart.db --out reports
```

Результаты сохраняются в `reports/`: CSV-таблицы и PNG-графики.
Для интерактивного анализа графиков можно открыть исходный ноутбук в Jupyter/Google Colab.

## Важные методологические оговорки

- В исходном задании указано падение выручки на 15%, однако без файла базы данных нельзя независимо подтвердить это значение.
- Если один заказ содержит товары нескольких категорий, `orders.revenue` нельзя целиком приписывать смартфонам. В расчётах выручка категории определяется как `order_items.price * order_items.quantity`.
- Средний чек категории рассчитывается как выручка смартфонов, делённая на число уникальных заказов, содержащих смартфоны.
- Расходы маркетинга сами по себе не позволяют корректно рассчитать ROI. Для этого нужны атрибуция конверсий, маржинальность, окно влияния и сопоставимые данные о продажах.
- Retention по брендам требует устойчивой привязки клиента к бренду/когорте. В текущей схеме когорта строится по первой покупке смартфона клиента, а повторная активность считается по месяцам.
- Скользящее среднее строится по доступным месяцам бренда. Если в данных отсутствуют месяцы без продаж, это не эквивалентно календарному трёхмесячному окну.
